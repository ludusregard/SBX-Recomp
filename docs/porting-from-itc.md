# Porting from ITC-Recomp

[ITC-Recomp](https://github.com/Spooky098529/ITC-Recomp) recompiles Import
Tuner Challenge, the US release of the same game, with the same SDK. This
project started from it: the layout, the build, the codegen loop and the
tools follow it, and the names in `docs/functions.md` come from its
`docs/functions.md`. This is the one doc about that relationship; the rest
of the repo describes SBX on its own.

A checkout of ITC-Recomp is a read-only reference. Its location is the
user's; tools take it as an argument (`<ITC-Recomp>` below).

## How the two line up

| ITC-Recomp | Here |
|---|---|
| `itc/` (game files, not committed) | `assets/` |
| `itc_recomp/` | `sbx_recomp/` |
| `itc_manifest.toml`, `itc_functions.toml` | `sbx_manifest.toml`, `sbx_functions.toml` |
| `itc_recomp/tools/` | `sbx_recomp/tools/` (the same scripts, plus ours) |
| `patches/rexglue-sdk/` | `patches/rexglue-sdk/` (none yet) |
| `docs/functions.md` | `docs/functions.md` |
| `CLAUDE.md` | `CLAUDE.md` |
| Builds on Linux, Windows cross-compiled | Builds on Windows (`*.bat`); Linux presets kept |
| Generated code committed and edited in place (`PATCH:`) | Regenerated by the build; edits go in overrides in `src/hooks/` |

Same SDK commit (`c94f5eb`, v0.10.0). ITC's SDK patches (glow and motion
blur, keyed to its shader hashes; SDL as a DLL, for its own renderer) aren't
used here yet.

## The two images

| Section | SBX | ITC |
|---|---|---|
| `.rdata` | `82000600`, size `73BE4` | `82000600`, size `76DC4` |
| `.text` | `82090000`, size `53138C` | `82090000`, size `54C064` |
| `.data` | `825F0000`, size `38A77C` | `82600000`, size `37833C` |

Code moves by a few hundred bytes at a time, so only 86 of ~5,000 function
entry addresses are the same in both: matching goes by content. 15,963
functions here, 16,315 in ITC.

## Matching

`sbx_recomp/tools/match_funcs.py` compares the instructions in the two
generated trees, with addresses and global offsets masked, and pairs
functions in passes: identical and unique (`exact`), identical up to
register allocation (`shape`), callees at the same spot of matched callers
(`calls`), between matched neighbours (`order`, `gap`), near the address
the nearest exact matches predict (`local`), by where a thunk branches
(`target`), and hand-checked pairs from `tools/match_pins.tsv` (`pinned`).
`tools/port_addrs.py` ports addresses: functions by their match, code
addresses to the aligned instruction of the matched function, data by
pairing the globals that aligned `lis` + offset instructions build ("n
refs"; "via X+n" = same offset from the nearest referenced address,
layout assumed).

How sure: **exact** (identical masked code, or up to registers); **checked
by hand** (`match_pins.tsv`, with the reason); **high** (similarity 0.95
and up, or every call to an already matched function lands on its match,
"agree n/n", with similarity 0.8 and up); **check** (plausible, confirm in
Ghidra). `FAR` = placed away from its ITC neighbours.

13,839 of ITC's functions are matched (2026-10-17), all in
`docs/itc_to_sbx_functions.tsv`; of the 10,052 with calls to matched
functions, 9,904 agree on all of them. Part of the library code was built
differently in the two games (other register allocation and scheduling,
calls to out-of-line register save helpers such as `bl 0x8258c608` where
ITC saves inline), so library functions match exactly less often.

Regenerate (from `sbx_recomp/`):

    python tools\match_funcs.py <ITC-Recomp>\itc_recomp\generated\default generated\default -o ..\docs\itc_to_sbx_functions.tsv --want <ITC addresses, comma-separated>
    python tools\port_addrs.py <ITC-Recomp>\itc_recomp\generated\default generated\default ..\docs\itc_to_sbx_functions.tsv --from-file <ITC-Recomp>\docs\functions.md

## Checked by hand

- `sub_8218C240` = ITC `sub_8218E420` (post-race check) instruction for
  instruction, including `cmplwi cr6,r11,60`; ITC's fix is ported as an
  override.
- Fixed time step: ITC's 4 users of 1/60 and 8 users of 1/30 map exactly
  onto SBX's users of `0x820029C0` and `0x820029C4`, including the two
  `FAR` ones.
- `sub_82159540` (`Race::DrawStep`) is the same function in another build
  of the game: ITC's has three more calls to its `sub_82133AE8` storing
  into `+88`, and a field ITC writes at `+92` is at `+64` here. Port
  ITC's wrapper with care.
- ITC's `sub_82152CD8` (camera shake) has no match: no SBX function that
  reads the speed looks like it, and its callee `sub_82152BD8` has none
  either. Likely ITC-only, or inlined here.
- `sub_82128D10` (ITC `sub_821292B0`) is one of three identical
  4-instruction thunks, picked by its tail call.

## Tool changes from ITC's

`scan_ptrs.py` reads the section ranges from the image (ITC's are
hard-coded for ITC), drops candidates inside `.pdata` functions and XEX
import thunks, and accepts candidates on `.pdata` boundaries
(`docs/codegen.md`). The other copied scripts use this project's names.
